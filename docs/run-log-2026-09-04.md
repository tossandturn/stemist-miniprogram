# Stemist 小程序长任务运行记录

## Checkpoint 01 · 设计基线与导航架构

- 当前目标：把 STEMist 微信小程序从“首页 + 几个独立 Demo”推进为统一产品入口，先冻结学生交互、文案、数据边界和手机/iPad 适配规则。
- 下一步依据：现有页面把 Practice/AI Coach 都映射到同一个 ActionSheet，且没有真实 Progress、Notebook、真题目录入口；先修信息架构和共享组件，后续功能才能复用同一条学习链路。
- 已排除的失败路径：不继续沿用四项底部按钮的隐式事件；不把完整 PDF/Apple Pencil 强行塞进小程序；不把本地示例数量或离线提示宣称为正式题库/成绩；不采用生成器建议的深色粉色替代品牌。
- 最近验证结果：
  - `py -3.12 ...ui-ux-pro-max.../search.py ... --design-system` 返回设计建议；已按生产 IELTSist/STEM token 覆盖通用建议。
  - 新增 `docs/mini-program-redesign-v2.md`，冻结页面职责、交互文案、数据链路、设备规则、视觉 token 和发布前置条件。
  - 新增共享 `components/app-nav`，并新增 Practice、Coach、Progress、Notebook、Past papers、Web workspace 页面骨架。
  - `npm run test:all`（截至新增页面/导航/题库适配前后的阶段性运行）通过；WXML/WXSS 编译通过；原有 `project.config.json` 本地 AppID 改动未提交。
- 退出条件：共享导航和页面契约先通过；下一 checkpoint 必须完成真实题库目录、Progress/Notebook 数据链路和所有输入页的重试状态，再进入视觉/设备专项验收。

## Checkpoint 02 · 功能迁移与数据闭环

- 当前目标：把设计基线变成可操作页面，并补齐真实题库、学习记录、Notebook、AI 重试和安全 WebView 数据链路。
- 下一步依据：导航骨架通过后，学生最明显的缺口是“点进去没有真实内容/失败后不能恢复”；因此优先做服务器数据和状态闭环，而不是继续装饰首页。
- 已排除的失败路径：
  - 不再用 ActionSheet 同时冒充 Practice 与 Coach；已迁移为独立页面。
  - 不把本地硬编码题量当真题库；Past papers 读取 `/data/papers/{subject}.json` 并过滤 active QP。
  - 不在 WebView 接受任意 URL；只允许 `https://stem.ieltsist.com` 与 `https://ieltsist.com` 精确主机。
  - 不在退出账号后保留另一位学生的 Notebook；会话清理覆盖 Notebook 与待同步 attempt。
  - 不让旧基础库把“拍照”退化为相册；`chooseMedia` 不可用时只用 `chooseImage({sourceType:['camera']})`。
- 最近验证结果：
  - 新增 Practice、AI Coach、Progress、Notebook、Past papers、Web workspace，共 16 个 app pages。
  - 26 条 STEM route 继续由共享 catalog 驱动；真实 paper catalog 会话内缓存，withdrawn/non-QP 不进入学生列表。
  - Progress 读取本机提交与 `/api/stem/attempts`；Notebook 使用 `/api/stem/notebook/notes` 并有本机/云端区分。
  - AI Coach、Listening、Reading、Writing、STEM photo 均有保留原始输入的错误/重试状态；STEM 同步成功后清理 pending，未登录时保留待同步证据摘要。
  - `npm run test:all` exit 0：架构、API、auth、session、Coach、attempt、inventory、26 路由、裁剪、设备、相机、图片、16 页、统一导航、paper catalog、learning summary、WebView 白名单和 WXML/WXSS 编译全部通过。
- 退出条件：下一段必须完成视觉 token 单一真源、移除结构性字符图标、手机/iPad 竖横屏几何检查、开发者工具可观测验收；任何新红测先修再推 GitHub。
