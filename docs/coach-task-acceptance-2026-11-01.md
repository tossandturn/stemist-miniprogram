# AI Coach 三档思考与可选保存任务验收

日期：2026-11-01，Asia/Shanghai。本记录区分开发工具、真实生产接口和物理设备，不能用接口正常代替真机验收。

## 最终规则

- 学生界面只有“快速 / 深入 / 极致”，三档默认开启思考；学科答疑默认“快速”。旧的手动偏好仍受尊重，阅卷和独立顾问的场景默认不改。英文协议枚举仅留在内部请求中。
- 普通即时答复不进入保存任务列表；只有“深入 / 极致”显示“保存为任务”，默认不勾选。勾选后结果从提交时间起保留 3 天；不新增原图存储。
- 未保存的即时结果仅在服务内存中保留 10 分钟用于断线恢复。磁盘只留短时幂等墓碑，不含答案、结果、题目正文、图片或模型细节。既有学习记录、对话草稿功能未被删除。
- 老客户端未传保存选项时兼容原 24 小时恢复；不进入新的保存列表，不延长已有行的到期时间。
- 普通题以约 30 秒内返回为目标，不承诺所有问题；复杂度、档位、网络和模型负载影响耗时。初始区间和近期同类样本的统计估计有明确区分，超时预估不伪装成持续倒计时。

## 验证结果

PASS：`npm run test:all`，含微信 WXML/WXSS 编译。构建两次一致；最终包执行 16 项任务/压缩相关套件及 26 项已有打包套件。主包安全余量仍高于 128 KiB，未降低门禁；为腾出空间只调整构建压缩选项，计算器逻辑未改。

PASS：真实生产接口 + 独立合成账号，在微信开发者工具中验证：

- 快速即时答复真实返回，未进入已保存列表；思考启用状态来自服务端元数据。
- 图片题完整答复样例 12.433 秒；图片准备 127 ms、上传准备 711 ms、模型处理约 11.016 秒。仅为单次合成样例，不是全站 SLA 或普遍提速比例。
- 注入一次查询响应丢失后恢复，仍只有 1 次模型任务 POST；上传显示真实已确认字节，分析无伪造百分比。
- 深入任务确认后离开页面再取回结果；创建时间与到期时间相差准确的 259200000 ms。后续另一真实任务样例 18.226 秒。
- 未登录 401，另一账号读取 404，无答案返回；快速模式保存、错误类型保存参数在调用模型前被拒绝。
- 生产库只读聚合核对：即时答案/结果持久化行数 0，错误保存时长行数 0，旧行到期变更行数 0。匿名耗时样本不带 owner/jobId/正文。
- 原生截图发现并修复窄卡片；390 px 视口内内容宽 358 px，卡片宽 358 px，工具按钮约 89.3 px。最终原生选择器验证三个中文名称、开启思考提示及仅深入/极致可保存。
- 所有测试均恢复本机原始会话/存储；无凭证导出。一个自建题目测试文件已清理，可由合成脚本重新生成；未删除用户图片。

测试工具问题已区分并复核：首次试图从尚未加载的分包读取测试服务失败，改为直接验证同一已完成任务，没有再次生成；原生选择器不支持的标签查询改为类名查询后，布局验证通过。最终已知失败状态不会显示成“仍在确认”。
