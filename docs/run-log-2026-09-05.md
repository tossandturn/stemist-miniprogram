## Checkpoint 03 · 右上角 AI、账号接续与运行时绑定

- 当前目标：让 AI Coach 在所有页面保持可见且不遮挡内容；点击首页右上角微信登录直接走 `wx.login`，并让 STEM/IELTSist 网页工作区能在不泄露 bearer token 的前提下接续账号。
- 下一步依据：截图中 AI 入口在底部、登录是页面跳转，且有路由缺失错误；学生进入完整网页时如果重新登录，会破坏“一个学习账户”的主线。因此把 AI 入口统一成右上角固定/首页右上角内联按钮，增加一次性 handoff，并保留本机模式作为网络失败回退。
- 已排除的失败路径：
  - 不在 query、日志或小程序存储中放 access token、session_key 或 App Secret；handoff 只存服务端哈希、一次消费、两分钟过期。
  - 不把 ieltsist token 直接发送到 STEM 或反向发送；两端通过已签名的本地服务端桥接。
  - 不用固定端口做测试；IELTSist 微信换票测试动态分配 loopback 端口，避免 Windows `EADDRINUSE`。
  - 不把 `eval` / `Function()` 的公开计算器源码直接导入；本机解析器通过表达式安全测试。
- 最近验证结果：
  - 小程序 `npm run test:all`：exit 0；18 页、原生相机、四入口、右上角 AI、WeChat auth、WebView handoff、14 学科目录和 WXML/WXSS 均通过。
  - STEM candidate `node scripts/test-stem-native-auth.mjs`：exit 0；本地 STEM handoff 的开放重定向、单次消费和跨 IELTSist 内部桥接通过。
  - IELTSist `npm run test:wechat-mini-auth`：exit 0；WeChat code2session 与 IELTSist WebView handoff 通过。
- 退出条件：必须完成 DevTools CLI/真机操作证据；在授权仍不可用时不伪造“已验收”截图。随后只提交意图内文件，推送 GitHub 并等待 Actions 绿灯；服务器变更前重新跑生产 readiness gate。
