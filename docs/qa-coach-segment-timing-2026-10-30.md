# AI Coach 分段计时与针对性提速验收

日期：2026-10-30，北京时间。后端运行版本 `220a498` 已部署；原生运行版本 `ae6dd65` 已上传微信开发版 **1.0.75**。尚未代替用户设置体验版、提审或正式发布。

## 改动

- 模型请求记录序列化、响应头、首个有效块、首个推理块到达、首段答案、完成及输出时长；仅记录数值，不记录推理内容。计时定义参考 [OpenTelemetry 原始仓库](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md) 和 [DeepSeek 流式接口](https://api-docs.deepseek.com/guides/thinking_mode/)，没有新增第三方依赖。
- 任务结果关联鉴权、图片请求准备和模型计时；客户端区分图片准备、提交确认、首次可展示回答、轮询等待与全程。提交确认包含网络与鉴权，不冒充纯上传测速。服务端与客户端时钟不直接相减。
- 小于等于 2048 px / 768 KiB 的已处理正向图片，不再重复压缩；方向未知、大图和不支持的源格式保留原处理路径。
- 轮询间隔扣除网络往返时间；故障退避、幂等任务、断线取回不变。
- 完整解答保持“答案—步骤—检验”，减少重复摘要与非必要第二种算法；仍保留关键推导、条件、单位，不关闭必要推理、不换模型。

| 合成测试题 | 原链路完成 | 新链路完成 | 新链路图片准备 | 模型调用总时长 |

新链路的模型首段答案分别为 3.528 s / 3.152 s，后续输出为 0.845 s / 1.566 s。业务准备只有 5 ms / 4 ms。主要等待仍在上游网络、排队、读图与生成的合计路径，不能进一步冒称测到了提供方内部的纯推理时间。

另做 6 组真实 API 配对实验（两题，各 3 对，保留 enabled/low 推理），12 个答案的结果、关键推导和完整公式已核对。图像题输出时长中位数 1.815→1.206 s，微积分 2.227→1.977 s；完成时间中位数分别 5.799→4.956 s、6.549→5.667 s。但微积分有一对候选反而用了 10.055 s、原版 7.457 s，说明上游波动仍存在。样本小，不能据此宣称所有真机都稳定 5 秒，也不是用户此前 30 秒原图的重放。
